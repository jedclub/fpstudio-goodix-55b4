# 접촉 중심 앵커 회전과 v8

## 문제

이 작은 108×88 센서는 지문 전체가 아니라 일부만 본다. 손가락이 센서 한쪽으로
치우친 상태에서 회전하면, 물리 이미지 중앙을 피벗으로 하는 변환은 실제 접촉
영역에 불필요한 원호 이동을 만든다. 이동 후보가 이를 보정할 수는 있지만, 거친
격자와 정밀 재탐색의 후보를 낭비하고 화면상으로는 처음 좌표에 고정된 것처럼
보인다.

## v8 변환

각 비교마다 기준과 검사 영상에서 0/1 접촉 컴포넌트를 새로 추출한다. 변환은

`검사 접촉중심 + scale × rotation(기준 좌표 - 기준 접촉중심) + 잔차 이동`

이다. 잔차 이동과 회전/크기 탐색 범위는 v7의 제한을 그대로 유지한다. 접촉
중심은 지문 코어/델타가 아니며 저장하거나 다음 접촉의 기준으로 학습하지 않는다.
검사 영상, 기준 영상, GPU 셰이더, CPU 수치 검증, 내부 ROI 근거 및 특징점 진단이
모두 같은 변환식을 쓴다.

연구 화면에서는 하늘색 `+`가 이번 비교에서 변환된 기준 접촉중심, 주황색 `+`가
이번 검사 접촉중심을 뜻한다. 파란 테두리는 여전히 물리 가장자리를 제외한 비교
범위일 뿐 지문 중심이 아니다. 이전 v7 기록에는 앵커 선언이 없으므로 기존
이미지-중심 식으로만 렌더링한다.

## 검증

- 이미지 중앙이 아닌 피벗과 앵커를 이용한 합성 회전/크기 변환에서 GPU와 CPU
  점수가 일치하는 테스트를 추가했다.
- 기준 25장과 기존 독립 저장 185프레임은 v7과 같은 엄격한 조건에서 `166/185`를
  유지했다. 기존 통과가 줄지는 않았다.
- 이번 새 동일 손가락 20접촉은 같은 조건에서 v7의 `14/20`에서 v8의 `16/20`으로
  늘었다. 모든 프레임이 매 비교마다 새 접촉 앵커를 사용했음을 출력으로 확인했다.

이는 동일 손가락 개발 자료에 대한 회귀 검증이며, 타인 지문 FAR 또는 독립 FRR
검증이 아니다. 따라서 이 v8 변경은 연구용 Release 후보이며, PAM/KDE 시스템
인증 엔진에는 아직 설치하지 않는다.
