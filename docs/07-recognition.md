# 인식률 — 무엇이 실제로 인식을 망치고 있었는가

> 후속 검증: [09-matcher-audit.md](09-matcher-audit.md).
> 아래는 당시 등록본과 로그에 대한 조사 기록이다. 후속의 다른 등록본에서는
> 비교자·각도 수정만으로 문제가 해소되지 않았으며, 여기의 단일 원인 해석이나
> 연속 인증 설명을 모든 세션에 일반화하지 않는다. matchlab의 호출 방향과
> 참조 검증 범위도 후속 문서에서 바로잡았다.

터치당 성공률이 70% 언저리였던 이유를 실측으로 추적한 기록이다. 결론부터
쓰면, 원인은 이미지 품질도 매처의 한계도 아니었다. **드라이버가 손가락이
올려진 상태에서 배경을 다시 찍고 있었다.**

---

## 0. 점수가 무엇인지부터

`libfprint/sigfm/sigfm.cpp` 의 `sigfm_match_score()` 가 돌려주는 값은
"일치한 특징점 수"가 아니다. 세 단계다.

1. Lowe 비율 0.75 를 통과한 대응점들을 모은다 → **N개**
2. 두 대응점을 잇는 벡터의 길이가 5% 이내로 같으면 `angles` 에 넣는다 → **A개**
3. `angles` 중 방향까지 5% 이내로 같은 **쌍의 개수**를 센다 → 이것이 점수

2·3단계가 각각 제곱이므로 **점수는 대응점 수의 약 4제곱**으로 커진다.
임계값 72는 기하적으로 일관된 대응점 6개 정도에 해당한다(6개면
A=15, 쌍=105).

이 구조를 알아야 실측 분포가 설명된다. 성공은 77~2920(그리고 30849까지),
실패는 0이나 7 — 중간이 거의 없다. 4제곱 함수는 원래 그렇게 생겼다.

## 1. 실측: 배경 차이가 결과를 가른다

저널에 남은 캡처를 전부 뽑아, 각 캡처의 `diff vs background` 값과 그 캡처가
15개 등록본에 대해 받은 최고 점수를 짝지었다.

| 배경 차이 | 접촉률 | 선명도 | 최고 점수 | 결과 |
|---:|---:|---:|---:|---|
| 725.7 | 75% | 30 | 3408 | 일치 |
| 816.9 | 75% | 34 | 143 | 일치 |
| 722.1 | 75% | 33 | 60 | 근소 실패 |
| 710.5 | 73% | 31 | 3 | 실패 |
| 311.4 | 68% | 31 | **0** | 실패 |
| 272.2 | 73% | **66** | **0** | 실패 |
| 206.8 | 69% | 54 | **0** | 실패 |
| 210.9 | 62% | 29 | **0** | 실패 |
| 136.2 | 65% | 57 | **0** | 실패 |

**배경 차이가 320 미만인 캡처는 예외 없이 15개 전부에 대해 정확히 0점이었다.**
낮은 점수가 아니라 0점이다. 그리고 그 캡처들의 선명도는 54, 57, 66 — 일치한
캡처(30, 34)보다 오히려 높다.

접촉률도 62~73%로 정상이다. 약하게 눌러서 생긴 일이 아니다. 정상 접촉률 +
높은 선명도 + 배경 차이만 낮음 + 0점. 이 넷을 동시에 설명하는 가설은 하나뿐이다.

## 2. 원인

`goodix55x4.c` 의 스캔 상태 기계는 `SCAN_STAGE_CALIBRATE` 로 시작하고,
그 단계는 이렇게 되어 있었다.

```c
static void on_scan_empty_img(FpDevice *dev, guint8 *data, ...) {
  FpiDeviceGoodixTls55X4 *self = FPI_DEVICE_GOODIXTLS55X4(dev);
  decode_frame(self->empty_img, data);   /* 무조건 */
  fpi_ssm_next_state(ssm);
}
```

센서에 무엇이 올려져 있는지 **확인하지 않는다.** 그리고 이 스캔 상태 기계는
세션당 한 번이 아니라 **검증 시도마다, 등록 단계마다** 새로 시작된다
(`dev_change_state` 가 `AWAIT_FINGER_ON` 마다 `scan_start` 호출).

그래서 손가락을 올려둔 채 다음 시도가 시작되면:

1. **그 손가락이 배경이 된다.**
2. 터치 감지가 죽는다 — 올려둔 손가락과 배경의 차이가 0이니까. 10초 폴링
   후 포기한다. **"뗐다 다시 올려야 반응한다"는 증상이 이것이다.**
3. 그 다음 캡처는 지문에서 지문을 뺀 이미지가 된다. 국소 지표는 전부
   정상으로 나온다 — 오히려 좋게 나온다(엣지가 늘어나므로 선명도 상승) —
   그리고 아무것과도 일치하지 않는다.

## 3. 등록본까지 오염되어 있었다

등록도 같은 경로를 탄다. 단계마다 재보정하므로, 등록 중 손가락을 센서 근처에
두고 있으면 그 단계가 오염된다.

현재 등록본(15단계)을 열어 각 단계가 나머지 14개 중 몇 개와 일치하는지 셌다.

```
  stage  kp   best  matches
      0  146    490     4
      1  143    861     4
      2  153     54     0   <- 아무것과도 일치하지 않음
      3  170   7519     2
      4  228      0     0   <- 아무것과도 일치하지 않음
      5  202      0     0   <- 아무것과도 일치하지 않음
      6  174   4819     2
      7  151    257     1
      8  100   1045     4
      9   92  30849     3
     10  115   4035     4
     11  124   2768     1
     12  117     60     0   <- 아무것과도 일치하지 않음
     13   72      5     0   <- 아무것과도 일치하지 않음
     14   86  25219     3
```

**15개 중 5개가 죽은 칸이다.** 그리고 4·5번 단계는 특징점이 228개, 202개로
전체에서 **가장 많다.** 특징점이 가장 많은 단계가 아무것과도 일치하지 않는
것 — 이것이 "구조화된 잡음"의 서명이다. 진짜 지문이라면 특징점이 많을수록
일치가 잘 된다.

## 4. 두 번째 문제 — 매처의 중복 제거

`sigfm.cpp` 의 대응점 중복 제거용 `std::set` 비교자:

```cpp
bool operator<(const match& right) const {
    return (this->p1.y < right.p1.y) ||
           ((this->p1.y < right.p1.y) && this->p1.x < right.p1.x);
}
```

둘째 절이 `==` 가 아니라 첫째 절을 그대로 반복한다. 전체가 **"행 번호로만
정렬"** 로 축약된다. 유효한 strict weak ordering 이므로 `std::set` 은 불평
없이 받아들이고, 그 다음 **같은 행에 있는 대응점을 전부 중복으로 보고 첫
번째만 남긴다.**

이미지 없이 컨테이너만으로 재현했다 — 서로 다른 대응점 40개(20행에 걸쳐
행당 2개)를 넣으면 **10개만 남는다.**

§0에서 본 대로 점수는 대응점 수의 4제곱이다. 4개 중 3개를 버리는 것은 4배
손실이 아니다.

## 5. 무엇을 고쳤나

- **`0013`** — 배경 보정 전에 센서가 비어 있는지 확인한다. 이미 갖고 있는
  배경과 새로 읽은 프레임의 차이가 60 미만일 때만 교체한다(빈 센서 잡음은
  4~5, 손가락은 700+ 이므로 그 사이). 손가락이 올려져 있으면 이전 배경을
  그대로 쓴다. 폴링이 10초를 다 쓰고 실패하면 배경을 버려서, 최초 보정이
  손가락을 잡았더라도 그 상태가 세션 내내 고착되지 않게 한다.

- **`0014`** — 비교자를 `operator==` 가 이미 의미하던 순서로 고친다. 고치고
  나면 대응점 수가 우연에 의해 제한되지 않으므로, 4제곱 비용을 위해 상한
  64개를 명시적으로 둔다(Lowe 비율이 좋은 것부터). 실측 등록본에서 96으로
  올려도 판정이 하나도 바뀌지 않았다 — 잘리는 것은 약한 대응점들이다.

## 6. 부수 효과 — "떼지 않고 연속 인식"

배경이 안정되면, 실패 후 다음 시도의 폴링이 **올려둔 손가락을 즉시 감지한다**
(깨끗한 배경 대비 차이 700+). 뗐다 붙일 필요가 없어진다. 재시도 20회가
손가락을 대고 있는 몇 초 안에 소진되며, 그동안 손가락이 미세하게 움직이면
서로 다른 배치가 표본으로 들어간다.

즉 연속 스캔은 별도 기능이 아니라 **`0013` 이 원래대로 돌려놓는 동작**이다.

## 7. 측정 도구

`tools/matchlab/` 에 있다.

- `matchlab` — 등록본(`.fp`) 또는 캡처(`.png`)를 받아 매처 변형들을 A/B
  한다. 판정 규칙은 드라이버와 같다(15개 중 **하나라도** 임계값을 넘으면
  통과, `fpi_print_sigfm_match` 참조).
- `selftest` — `matchlab` 의 기준 변형이 설치된 매처와 **점수까지 동일한지**
  검증한다. 이게 통과하지 않으면 A/B 결과는 아무 의미가 없다.
- `dumpprint` — 등록본의 단계별 특징점 수를 본다.
- `analyse.py` — 캡처 여러 장에서 **공통으로** 올라타 있는 성분(고정 패턴
  잡음, 열/행 편향)을 찾는다. 모든 이미지의 같은 자리에 생기는 구조는 어떤
  두 이미지끼리도 일치하므로, 잡음보다 나쁘다 — 매처에게는 신호로 보인다.

기준 변형이 설치된 매처와 일치함을 확인한 뒤에만 숫자를 믿을 것.
