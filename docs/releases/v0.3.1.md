# FPStudio v0.3.1

v0.3.0 was tagged but never released: its workflow failed on a patch that had
been generated against the wrong source tree, so no package was ever produced.
This release carries everything v0.3.0 described, with the settle rule
corrected and the lock screen fixed.

Read v0.3.0's notes for the changes this builds on.

## Changes

- Keep the strongest frame of a settling contact, not the last one. v0.3.0 took
  the third poll on the assumption that a finger keeps arriving; when it starts
  lifting instead, contact fades across the three polls (183.9, 152.5, 147.8)
  and the last frame is the worst of them. This is why the lock screen still
  failed after v0.3.0: an unlock is a quick tap, so its polls fall on the way
  out rather than the way in. Measured afterwards on the lock screen:
  `ncc=0.925`, all sixteen tiles, against 0.578 over eight tiles and 0.384 over
  four before.
- Build the driver patch against the sequence the package actually applies. The
  patch had been generated from a local tree carrying patch 0022, which the
  PKGBUILD deliberately omits, so its context never matched and the package job
  failed. It is now generated from a worktree reproducing the twenty patches
  the PKGBUILD applies, in that order, and verified by replaying the whole
  sequence and building.
- Keep frame reading ahead of map building on a slow device. Placing every
  frame on the map cost more than the sensor's frame interval and dropped
  contacts (29 of 33 in a recorded session). Placement now backs off to twice
  its own last cost, so it never outruns capture.
- Make the enrolment selection a function of a directory and test it. The
  greedy coverage pick was reachable only by running the window; it is now a
  pure function over what a session left on disk, with a test showing that ten
  sharp views of one corner lose to three ordinary ones that span the finger.
- Add an optional profile-guided build (`tools/pgo-build.sh`,
  `-DFPSTUDIO_PGO=GENERATE|USE`). It is off by default because it measured no
  change on this workload: 105.1ms against 103.1ms, inside run-to-run noise. An
  earlier 33% figure was an artifact of timing the two builds one after the
  other rather than interleaved.
- Compare translation strings rather than the lines they sit on. `lupdate`
  rewrites every `line=` attribute when anything above a string moves, which
  failed the catalogue check twice on commits that added no strings.
- Add `tools/fpdlg-shot.sh`, which captures the authentication dialog together
  with the PAM and polkit logs, for the KDE window that occasionally draws with
  its bottom clipped. That report is still open and unreproduced.

## Upgrade notes

- Re-enrol. The settle change alters which frame the sensor hands back, and a
  gallery captured under the old rule holds the frames this release avoids.
- Everything under v0.3.0's upgrade notes still applies, in particular that the
  driver patch is what fixes recognition and that biometric matching remains
  experimental, measured on one person's fingers rather than validated as a
  false-accept rate.

## Localisation

- Translate the enrolment and research windows. They held 124 Korean string
  literals that never went through `tr()`, so `lupdate` could not see them and
  every locale showed Korean: the enrolment window the person actually uses was
  18 strings in the catalogues against 81 hardcoded. They are now English source
  strings like the rest of the codebase, with the Korean moved into
  `fpstudio_ko.ts`, and all ten catalogues completed — 339 strings each, none
  unfinished.
- Guard it in CI. A Korean literal outside `tr()` now fails the build, because
  the existing catalogue check cannot see one: it passed while 81 strings were
  untranslatable. `i18n.cpp` is exempt, where the Korean is an endonym in the
  language picker.
- Stop forcing the capture helper into Korean. The research window passed
  `--lang ko` to its child, so a session in any other language switched to
  Korean the moment capture started.
