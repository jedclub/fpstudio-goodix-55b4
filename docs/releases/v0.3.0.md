# FPStudio v0.3.0

Authentication reads a settled contact instead of the moment one is detected,
and coverage maps are built by tracking a finger rather than assembling
separate touches.

## Changes

- Read the finger once it has arrived. Host-side detection polls the sensor
  against its background and previously captured the first frame over its
  threshold; an empty sensor reads 4-17 and a contact 130-206, so that frame
  was a fingertip touching at one edge. Over 32 live authentications the single
  acceptance covered all sixteen tiles of the sensor and correlated at 0.864,
  while the rejections covered as few as two tiles and correlated 0.14-0.67 -
  the right finger, caught on its way down. Three polls 100ms apart must now
  clear the threshold and the last frame is kept; the authentications measured
  afterwards read 13-16 tiles and 0.940-0.982.
- Track the contact when building a coverage map. Registration across a lift is
  accurate to about 5.5px on a sensor whose ridges repeat every 8-10px, while
  between frames of one uninterrupted contact it is 0.01-0.5px. The pose is
  carried forward while contact holds and searched for again only when it
  breaks.
- Search the whole map for a new contact rather than 60px either side of its
  centre, where a region further out could not be placed correctly at all and
  was forced into the nearest reachable position. The search is hierarchical,
  so it costs less than the narrow one it replaces.
- Reject a placement that is merely the best rather than the only plausible
  one. Ridges repeat, so a placement one period out scores nearly as well, and
  taking the maximum corrupted the map with confident mistakes.
- Raise the map registration floor from 0.30, which rejected nothing: other
  fingers placed on a finished map still scored up to 0.575. Tracking and
  anchoring now carry separate floors, because a frame that never lifted is not
  asking whether it belongs.
- Sample captures along the sweep. "The best frame of each contact" was written
  when a contact meant one press of one spot; sliding without lifting made a
  whole session one capture.
- Install the enrolment from the enrolment window. Captures are chosen by what
  each adds to the map's coverage rather than by sharpness alone, which on
  measured data took 21 sharp references (17 of 25 recognised) to 32 broader
  ones (20 of 25).
- Add `auth_install.py --refresh-gallery`, so re-enrolling no longer requires a
  rollback and a full reinstall of PAM, binaries and gallery together.
- Enforce the gallery directory mode the driver bridge requires. A 0755
  directory left by an earlier install disabled GPU matching for 93 consecutive
  authentications and fell back silently to a matcher that scored every capture
  zero. The installer now checks the bridge's preconditions and says so.
- Raise the acceptance floor from .70 to .86. Other fingers of the same hand
  reached .842 against this gallery while the enrolled finger stayed above
  .874. The floor is pinned by a test so lowering it has to be deliberate, and
  the gallery is refused if it was enrolled under a different matcher profile.
- Split the map's rejection counter by reason, so a smeared capture can be told
  from a placement that was not trusted.

## Upgrade notes

- The driver patch is what fixes recognition; a package rebuilt without
  `0023-goodix55x4-settle-before-reading-finger.patch` keeps the old behaviour.
- Existing enrolments and PAM settings are preserved by gallery-only and
  matcher-only refreshes. Both remain transactional and recoverable from the
  backup the installer records.
- Biometric matching remains experimental and is not validated as a
  false-accept rate. The separations quoted here were measured on one person's
  fingers; verify both fingerprint success and password recovery on the actual
  machine before relying on it.
