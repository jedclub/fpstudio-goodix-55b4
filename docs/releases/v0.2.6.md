# FPStudio v0.2.6

Experimental local authentication integration and terminal input-safety fixes.

## Changes

- Add an original LGPL PAM module and a separate fprintd sensor worker for
  supported sudo, sudo-i, Polkit, local TTY login, su and su-l profiles.
  Password submission uses the existing PAM password validator.
- Keep KDE's separate password service alongside its noninteractive fingerprint
  service. The lock-screen fingerprint path completes without Enter.
- Bound each sensor operation to 30 seconds and at most 20 retry events, with
  readiness, retry, failure and completion feedback. Slow sensor initialization
  has a separate regression test.
- Fix terminal input exposure windows at startup and on fingerprint completion.
  CLI matches complete automatically only if no key has been pressed. Any key
  latches Enter-required mode, even after erasing the input. Nonempty input goes
  to the normal password validator. Restore echo after cleanup and input flush.
- Add a red CLI Admin header, password-or-fingerprint prompt, `(1/20)` retry
  counter and `*` masking. The native password conversation runs on a private
  PTY; only the parent handles real keyboard input. Preserve sudo's explicit
  noninteractive/stdin/askpass paths and KDE's native desktop dialogs.
- Use the native KDE Polkit agent for desktop installation, not a Konsole
  authentication window. Separate password labels from concise sensor notices.
- Translate PAM notices into English, Korean, Japanese, Simplified/Traditional
  Chinese, Spanish, German, French, Russian, Italian and Portuguese. Select the
  system message locale with English fallback; do not read GUI preference files
  in privileged authentication code.
- Add reversible PAM deployment and GPU-engine refresh without reimporting
  private reference images or overwriting the existing enrollment.
- Align v8 GPU diagnostics and matcher-profile checks; bound wizard sensor tests
  and report thermal protection separately from ordinary no-match results.

## Verification

- CTest covers existing matching/research policies, concurrent PAM behavior,
  noninteractive multithreaded lock-screen cases and message localisation.
- PTY tests use synthetic passwords, including early typing, typing across a
  fingerprint match, retries and rejection of a wrong submitted password.
- Private D-Bus tests exercise the production worker without real biometrics.
- Local hardware checks observed successful sudo and Polkit operations and an
  actual fingerprint match followed by `Unlocked` in KDE greeter testing mode.
  Testing mode is not a full locked-session/wake/suspend validation.

## Limitations and upgrade notes

- This remains experimental biometric authentication. False-acceptance rates,
  other-finger rejection and spoof resistance are not security-certified.
- CLI automatic completion depends on an interactive foreground terminal.
  Colour falls back to plain text for unsupported terminals or `NO_COLOR`.
- GUI catalogues and PAM notices support eleven languages, but some advanced
  setup/recovery messages remain hard-coded in Korean. GUI manual language
  selection does not change the OS authentication locale.
- Only recognized local PAM layouts are modified. SSH, graphical greeter
  configuration, disk encryption and keyring decryption are outside this installer.
- Build from source, review the read-only installation plan, then explicitly
  apply via the wizard or `bash tools/activate_auth.sh`. Keep password access and
  the recorded root-owned backup. Already-open dialogs use their previous module.
- Release assets contain source and its SHA-256 checksum only: no firmware,
  fingerprint images/templates, private galleries, credentials or local binaries.
