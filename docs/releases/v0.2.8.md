# FPStudio v0.2.8

Reliable simultaneous fingerprint and password authentication for interactive
terminals, with privacy-safe diagnostics for the complete sensor and matcher
path.

## Changes

- Isolate CLI terminal input, termios state and signal handling in a dedicated
  child. Fixed-size local messages and a completion acknowledgement prevent
  fast Kitty/fish input, HUP or channel-close races from leaking the first
  password character, aborting sudo, or leaving terminal echo disabled.
- Keep fingerprint and password input available together. Fingerprint matches
  complete immediately until keyboard entry begins; after any key, masked
  input remains in Enter-required mode so trailing password bytes cannot reach
  the shell.
- Parse only sudo's own option prefix when detecting `-S`, `-A` and `-n`.
  Command arguments such as `sudo pacman -S ...` no longer disable the
  interactive fingerprint path by mistake.
- Preserve application signal handlers, foreground process-group ownership and
  terminal state across cancellation, fingerprint success and password
  submission. Sensor workers are reaped promptly on timeout or failure.
- Add structured journald timelines across PAM, the isolated fprintd worker,
  sensor contact/capture, GPU matching, Vulkan reinitialisation and SIGFM
  fallback. Install `fpstudio-auth-report` for privacy-safe failure summaries;
  passwords, usernames and biometric material are never logged.
- Upgrade legacy PAM control lines to fail closed on internal aborts while
  retaining the normal system password validator. Extend the interactive
  window to 60 seconds with the existing 20-event bound.
- Prohibit shell functions, aliases and nested pseudo-terminal wrappers around
  `sudo` in CI. FPStudio now owns status rendering inside PAM; old output
  wrappers must be removed because they detach the controlling terminal.
- Repair two malformed unified-diff headers inherited by v0.2.7 and add a fast
  syntax gate before the complete pinned-source driver package build.

## Verification

- Full CTest suite: 22/22 passed, including sudo option-boundary, localisation,
  concurrent PAM, GPU/CPU parity and log-report tests.
- Thirteen real PTY scenarios passed for password masking, fingerprint match,
  HUP, rapid startup input, retry, erase, cancellation, overflow and Unicode.
- Installer and privacy-safe log reporter unit tests passed.
- The complete driver patch series applied to the pinned upstream revision and
  produced the Arch package successfully.
- Local Kitty/fish reproduction confirmed that typed input remains masked and
  the worker reaches `sensor_ready` through both direct sudo and a stale-shell
  compatibility launcher. A recent hardware authentication completed through
  the Vulkan matcher before release preparation.

## Upgrade notes

- Open a new shell after upgrading if it previously defined a `sudo` function.
  Remove any legacy output-filter wrapper and verify `type -a sudo` resolves to
  `/usr/bin/sudo`.
- Repeated back-to-back hardware tests can trigger the Goodix thermal guard.
  Let the sensor return to sleep before retrying; password fallback remains
  available.
- This remains experimental biometric authentication. Keep a tested password
  path and the root-owned PAM rollback backup.
