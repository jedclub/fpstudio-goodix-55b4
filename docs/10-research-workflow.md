# 지문 연구의 실행 흐름

## 역할 분담

fpstudio의 연구 창이 사람과 센서 사이의 반복 절차를 관리한다.
MCP 클라이언트는 세션을 시작·조회·중단하고 결과를 분석한다.
개별 촬영의 안내 시점이나 다음 촬영 진행을 에이전트 응답 시간에 의존하지 않는다.

```text
프로그램 실행 → 손가락 떼기 5초 → 빈 센서 배경 측정
         → 배경 측정 완료 신호 → 지금 대기 → 실제 접촉 확인
         → 촬영 → 손가락 떼기 → 영상·품질 표시 4초 → 다음 준비
```

`activated`는 배경 측정 완료를 뜻하지 않는다. 연구 창은
`SCAN_EMPTY_NUM completed successfully`에서 만들어지는 `background-ready`
신호를 기다린 뒤 손가락을 대도록 안내한다. 0015 실험 패치는 원본의 조기
finger-on 보고를 제거하고 실제 배경 차이가 접촉 임계값을 넘은 뒤 보고한다.

## 고정 수집 계획

| 단계 | 손가락 | 수량 | 역할 |
|---|---|---:|---|
| 기준 | 오른쪽 검지 | 6 | reference |
| 별도 검증 | 오른쪽 검지 | 4 | probe |
| 다른 손가락 | 오른쪽 중지 | 4 | probe |

기준·동일 손가락 검증에서는 중앙을 반복 촬영한 후 아주 작은 좌우 이동을
포함한다. 시작·단계 전환 모두 카운트다운으로 자동 진행하며 버튼은 중단 하나다.
같은 샘플을 연속 3회 촬영하지 못하면 자동 진행을 멈춘다. 사용자는 언제든
중단할 수 있으며, MCP의 `resume_collection`으로 원인 확인 후 같은 샘플부터 재개한다. 저장 실패나 센서 오류를 인증 불일치로
해석하지 않는다. 수집 완료도 인증 성공 판정이 아니다.

## 실행과 MCP

```bash
cmake -S src/fpstudio -B src/fpstudio/build
cmake --build src/fpstudio/build -j 4
./src/fpstudio/build/fpstudio --research
```

MCP 서버는 `fpstudio --mcp`로 실행한다.

| 도구 | 역할 |
|---|---|
| `start_collection` | 연구 창을 열고 자동 수집 시작 |
| `collection_status` | 상태, 완료 수, 샘플 경로, 품질 조회 |
| `stop_collection` | 중단 요청, 기존 저장 자료 보존 |
| `resume_collection` | 반복 실패로 일시정지한 세션을 진단 후 재개 |
| `capture_image` 등 | 세션 밖에서 개별 진단에 사용. 연구 세션 중에는 거절 |

GUI 프로세스, MCP 서버, 연구 세션 각각에 `QLockFile`을 사용한다.
동일 사용자에서 중복 프로세스를 시작하면 종료 코드 3으로 거절한다.
연구 창의 CLI 캡처 자식 프로세스는 필요한 작업자이므로 GUI 중복에 포함하지 않는다.
이전 빌드처럼 잠금 기능이 없던 프로세스는 새 빌드로 교체할 때 먼저 종료한다.

세션별 `capture-status.json`으로 자식 프로세스의 진행 상황을 전달하고 PID도
대조한다. 다른 CLI나 MCP 배너가 연구 창의 촬영 지시를 덮어쓰지 않는다.

## 저장과 분석

기본 저장 위치는 Git에서 제외된 `local-private/recognition/session-날짜/`다.
폴더는 0700, 영상과 JSON은 0600으로 보관한다.

- `session.json`: 현재 상태와 reference/probe 구분, 손가락 라벨, 품질, 시도 기록
- `attempt-NNN.json`: 캡처 결과와 진단 로그. 장치 고유 정보가 포함될 수 있어 비공개
- `reference-index-*.png`: 기준 영상
- `probe-index-*.png`, `probe-middle-*.png`: 별도로 촬영한 검증 영상

`matchlab --heldout ref:index=기준파일 probe:index=검지검증파일 probe:middle=중지검증파일`
형식으로 평가한다. 여러 파일을 반복해서 전달할 수 있다. probe는 reference로
재사용하지 않는다. 기존 leave-one-out 내부 일관성 수치와 별도 검증을 구분한다.
4장의 다른 손가락이 모두 거절되어도 일반적인 오인식률을 확정할 수는 없다.

## 자동 검증

```bash
ctest --test-dir src/fpstudio/build --output-on-failure
```

가짜 캡처 자식 프로세스로 배경 준비 신호, 전체 14장 진행, 단계 전환,
reference/probe 분리, 3회 실패 정지, 중단, 연구 세션 중복과 GUI/MCP 프로세스
중복 차단을 시험한다. 이 시험은 USB를 열지 않으며 실제 인식률 시험을 대체하지 않는다.

## 연속 미리보기와 자동 후보 선택 (`--live`)

Vulkan 다중 기준/정렬 병렬 비교를 연결하는 방법과 측정 결과는
[Vulkan 병렬 매칭](11-vulkan-matching.md)에 정리한다.

2026-09-07 실제 55b4에서 108×88 영상을 연속 수신하면서 화면 갱신 약
16.4 FPS를 확인했다. 목표는 최소 15 FPS이며, 25 FPS는 과거 단일 읽기
40 ms를 역산한 추정일 뿐 달성한 연속 속도가 아니다. 화면 FPS는 타이머
설정값이 아니라 새로운 센서 타임스탬프의 프레임을 표시한 수로 계산한다.

0015 및 0016은 현재 로컬 연구용 드라이버 패치이며 시스템 패키지에는
아직 포함하지 않았다. 0016은 `GOODIX55X4_PREVIEW_PATH`가 설정됐을 때만
작동하며 보정과 TLS 연결을 유지한 채 GET_IMAGE를 반복한다. 중간의
FDT 접촉 전환 대기를 생략하므로 손을 계속 대고 있어도, 떼고 있어도
영상이 갱신된다. 일반 등록·인증 경로의 품질 임계값을 낮추지 않는다.

로컬 드라이버 소스에 0015, 0016을 적용하고 ninja로 빌드한 뒤 저장소 루트에서:

```bash
LD_LIBRARY_PATH="$PWD/src/driver/src/libfprint-goodixtls-55x4/build/libfprint" \
  src/fpstudio/build/fpstudio --live --lang ko
```

실행 → 손 떼기 5초 → 배경 보정 → 연속 영상 및 위치·압력 조절 안내.
중단 버튼 하나이며 GUI/연구 잠금을 공유한다. 1.5초 동안 새 영상이 없으면
0 FPS와 정지 영상 경고를 표시한다. 스트림은 최대 3분이며 작업자는
195초 제한, 중단 시 정상 종료 요청 후 3/5초에 종료/강제 종료한다.

`local-private/recognition/live-날짜/`에는 최신 PGM 한 장만 덮어쓰며
전체 동영상은 저장하지 않는다. 후보는 접촉 그룹당 최고 한 장, 최대 30그룹이다.
접촉 해제 신호가 3프레임 이상 관측되어야 다음 그룹으로 센다.

선별 v1은 신호 차이≥100, 명암 면적≥62%, 선명도≥16, 8×8 블록의
방향 일관성≥0.45(유효 블록≥20), 직전 프레임 평균 절대 차이≤18을
3프레임 연속 충족해야 한다. 선명도 점수는 50에서 제한해 고주파 잡음의
무제한 가산을 막는다. 이는 실험용 화질 휴리스틱이지 학습된 지문 판별기나
인증 판정기가 아니다. 줄무늬 인공물도 통과할 수 있고, 접촉 그룹 분리는
배경 차이 임계값에 의존한다. 후보의 손가락 라벨도 확인 전에는 미확정이다.

후보 PNG와 점수·접촉 그룹 메타데이터, 진행 JSON은 비공개로 저장한다.
후보를 자동으로 시스템에 등록하지 않는다. 별도로 손을 뗐다 댄 촬영과
다른 손가락을 사용해 정확도를 평가해야 하며 이웃 프레임을 reference/probe로
나누어 성능을 부풀려서는 안 된다.

자동 시험에는 합성 프레임의 연속 표시/FPS 측정, 단일 접촉 중복 억제,
평탄 영상·접촉 부족·저대비·움직임 배제, 스트림 정지 감지 및 중단도 포함한다.
