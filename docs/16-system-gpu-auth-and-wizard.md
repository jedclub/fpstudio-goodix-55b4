# 시스템 GPU 인증과 통합 위저드

## 구현한 연결

sudo / polkit / TTY / KDE 잠금 화면 → pam_fpstudio → 기존 fprintd의 사용자·등록 선택
→ libfprint GPU 연결 → root 전용 영상 기준 → Vulkan 비교 → 결과 반환.

기존 등록 파일을 덮어쓰거나 재등록하지 않는다. 사용자의 기존 Goodix 등록에서
username이 일치하는지 설치 전에 공개 deserializer로 확인한다. 선택한 계정만
`/etc/fpstudio-auth-users/`의 root 소유 표식으로 GPU 경로를 활성화한다.
다른 계정은 기존 SIGFM 경로를 유지한다. 활성 계정의 데이터 손상·GPU 오류는
기존 SIGFM으로 우회하지 않고 인증 실패로 반환한다.

## 제한과 보안 상태

실험적 도입이다. 실제 다른 손가락 거절 성능/FAR과 위조 지문 저항성은 미검증이다.
연구 프리뷰의 초록 표시를 그대로 인증 성공으로 사용하지 않는다.
`authpolicy.h`는 NCC ≥0.70, 방향 상관 ≥0.65, 내부 겹침 ≥0.50,
지지 타일/검사 영상 타일 각각 ≥8, 모호하지 않은 정렬 및 탐색 경계 아님을 요구한다.
이 수치가 검증된 보안 수준을 보장하지는 않는다.

기존 SIGFM 특징점이 0이라는 이유만으로 GPU 비교 전에 영상을 버리지 않도록
root 설치 표식이 있을 때만 특징점 없는 영상의 비교 진입을 허용한다.
이 변경은 인증 허용 자체가 아니다.

helper는 setuid 프로그램이 아니며 root fprintd에서만 호출한다. username만 인자로
받고 정확히 108×88 PGM을 표준입력으로 전달한다. 일반 사용자 수정이 가능한
설치 파일·기준·심볼릭 링크·해시 불일치는 거부한다. GPU subprocess 환경은
초기화하며 helper 4초 / bridge 6초 제한, 부모 종료 시 GPU child 종료를 둔다.
비교 원본 임시 파일은0700 임시 폴더/0600 파일로 만들고 종료 시 제거한다.

## 설치와 복구

`tools/auth_install.py` 기본 동작은 읽기 전용 변경 계획이다.
실제 적용은 root 및 `--enable-experimental-auth --apply`가 필요하다.
시스템 배포판 libfprint를 덮어쓰지 않고 `/opt/fpstudio-auth/lib`의 별도 빌드를
fprintd systemd drop-in에만 지정한다. 기존 서비스 보안을 해제하지 않고 DRM 장치
접근만 추가한다. 유사한 systemd 보안 조건에서 기준 영상 자기 비교로
실행 경로를 검사한다. 이는 설치 smoke test이며 인식률 검증이 아니다.

선택한 세션의 실패 접촉은 가져오기에서 제외하고 중복 영상 해시를 제거한다.
계정별 기준은 `/var/lib/fprint/fpstudio-gpu/<user>`에0700/0600으로 보관한다.
원본 연구 데이터와 기존 fprintd 등록은 보존한다. 마지막 영상 후보를 가져오는
방식이므로 후보의 품질 점수와 인증 정책 통과 여부를 동일시하지 않는다.

지문·비밀번호 동시 입력은 `tools/dual_auth_install.py --apply`로 적용한다.
sudo·sudo-i·polkit·TTY login·su·su-l의 기존 비밀번호 검증을 유지하고,
KDE 잠금 화면은 별도 비밀번호 서비스와 병렬 지문 서비스를 유지한다.
센서는 전체 30초·최대 20회로 제한하며 준비·재시도·종료 메시지를 전달한다.
기존 `--repair-pam`은 표준 pam_fprintd의 직렬 경로 보정용이며 동시 입력이 아니다.
설치 범위·백업·복구·시험 방법은 [동시 입력 안내](21-simultaneous-auth.md)를 참고한다.

매처나 드라이버 브리지만 최신 빌드로 교체할 때는
`pkexec /usr/bin/python tools/auth_install.py --refresh-experimental-auth --apply`를
쓴다. 이 경로는 갤러리·fprintd 등록·PAM을 다시 만들지 않으며, 새 바이너리
해시를 기록하고 root 전용 기준의 자기 비교가 통과할 때만 유지한다.

원본 설정은 `/var/backups/fpstudio-gpu-auth/install-*`에 보관한다.
`--rollback <정확한 백업 폴더>`로 복구하며, 제거된 실험 파일도 백업 폴더로
이동해 보존한다. 설치 실패 시 자동 복구한다. 동시 관리자 설정 편집은 피해야 한다.

## 위저드

- 장치 → 드라이버 → 권한 → 명시적 통신/영상 시험 → 센서 키 확인 → 등록
  → 저장 지문/GPU 연결 → 관리자 창 → sudo → KDE 잠금 화면.
- 조회는 비동기이며 위저드 실행/새로고침만으로 USB 캡처를 시작하지 않는다.
- 통신 오류만으로 PSK 쓰기를 권하지 않는다. 쓰기는 명확한 불일치와 별도 확인이 필요하다.
- 기존 등록이 있으면 이를 보존한다. 없는 사용자는 fprintd 등록 과정을 진행한다.
- 설치·등록 중 다른 작업을 겹쳐 실행하지 못하게 하고 단일 GUI 잠금을 유지한다.
- GPU 연결, 시스템 fprintd 비교 시험, 설치 전 인증 설정 복구를 같은 창에서 실행한다.
- 필수 단계를 건너뛰었다고 완료 처리하지 않는다. 설치 완료와 sudo/KDE 실제 인증
  검증을 구분한다. 시스템 비교 시험은 sudo/polkit PAM 폴백 시험을 대체하지 않는다.

드라이버 초기 설치 도구는 Arch/CachyOS 전용이다. 고정 커밋으로 별도 캐시 폴더에서
일반 사용자 권한으로 makepkg를 실행하며 패키지 설치 때만 polkit 권한을 요청한다.
새 OS 전체 초기 설치, GPU 설치 자료 번들 배포, 모든 신규 등록/복구 경로의 실기
검증은 아직 완료되지 않았다. 펌웨어 자동 플래시나 지원하지 않는 센서 지원을
완료했다고 주장하지 않는다.

## 확인 상태

로컬 GUI/helper/driver 빌드 완료. CTest4개 묶음 및 Python 관리자 안내6개,
인증 설치4개, 고정 드라이버 recipe1개 시험 통과. 최근14개 GPU 결과를 새 정책으로
읽기 전용 재평가했을 때9/10접촉이 정책을 만족했다. 실제 인증 승인과 동일한
측정이 아니며, root 설치와 실제 sudo/KDE 시험 상태는 별도로 확인해야 한다.

2026-09-07 실제 root 설치를 완료했다. 기준44장, 세 PAM 서비스10회 설정,
GPU helper의 systemd 제약 조건 내 자기 비교, fprintd 재시작 및 GetDevices
호출이 통과했다. 원본 백업은
`/var/backups/fpstudio-gpu-auth/install-ourjm8nj`에 있다.
첫 설치 시도는 `/var/backups` 상위 폴더가 없어 변경 전 중단됐으며,
부모 폴더 생성 처리를 보완한 두 번째 시도가 성공했다.
실제 손가락으로 sudo/KDE 승인 및 실패 후 비밀번호 폴백은 아직 확인 전이다.
