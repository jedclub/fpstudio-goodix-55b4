# 노매치 감소를 위한 인증 후보 탐색 v6 (이전 기준선)

## 변경 범위

이 문서는 v6 후보 탐색 기준선의 기록이다. 현재 소스의 `--auth-search`는 접촉
영역 0/1 교집합을 추가한 v7이며, 상세는 [19-ridge-roi-v7.md](19-ridge-roi-v7.md)를
따른다. 아래 수치는 v6 당시의 재현 결과로 보존한다.

`fpstudio-vkmatch --auth-search`와 새로 빌드한 `fpstudio-auth-match`에 적용한다.
기존 연구 모드(v3/v4/v5)의 실행 옵션과 정책은 유지한다. 인증 모드와 연구용
빠른 갤러리 옵션의 혼용은 거부한다. 기존 설치된 `/opt/fpstudio-auth` 파일은
이 소스 빌드만으로 변경되지 않는다.

기존 코드는 내부 구조 종합 점수 1위만 인증 정책에 전달했다. 그 후보가 모호한
정렬이거나 겹침/타일 수가 부족하면 다른 기준 영상의 유효한 후보도 무시됐다.
v6는 기준 영상·전처리 경로별 최대 3개 독립 정렬 후보에 **동일한 기존 정책**을
적용한 뒤, 조건을 만족하는 후보 안에서 종합 점수로 선택한다. 전역 선택과
재탐색 후 기존 후보 보존에도 같은 순서를 적용한다.

인증 모드의 균일 확대·축소 범위는 0.95~1.05(±5%)다. 먼저 0.95, 0.97,
0.975, 1.00, 1.025, 1.03, 1.05를 GPU 배치로 비교하고, 실패 후보만 그 안에서 더 촘촘히
재탐색한다. 범위 밖, 가로·세로 비율을 따로 바꾸는 변환, 국소 탄성 변형은
허용하지 않는다. 내부 비교는 바깥 8픽셀을 제외한 4×4 타일의 명암과 융선
방향을 사용하므로 센서 프레임이나 잘린 영상 가장자리가 통과 근거가 되지 않는다.

기존의 연구용 `consistent` 판정이 아니라 실제 인증 조건 미충족을 기준으로
전체 회전 재탐색을 수행한다. 그래도 실패하면 상위 최대 8개 기준/전처리 경로에
대해 2단계 정밀 위치·회전·크기 탐색을 수행한다. 위치/각도 간격은 0.5와 0.25,
크기 간격은 0.02와 0.005, 각 축 ±2단계이며 크기는 계속 0.95~1.05로 자른다.
추가 가설은 최대 10,000개다.
기존 후보와 피크 간격을 비교하므로 GPU 샘플링 간격은 기존과 같은 2를 유지한다.

국소 타일을 독립적으로 휘거나, 실패 영상을 자동 학습하거나, 지문 무늬를
합성하지 않는다. 최종 증거는 계속 원본 영상의 내부 명암/방향 상관과
공간적으로 분포한 지지 타일에 기반한다. NCC 0.70, 방향 0.65, 겹침 0.50,
각 타일 수 8, 비모호 정렬, 탐색 경계 배제 조건은 낮추지 않았다.

후보를 더 많이 검토하면 임계값이 동일해도 오수락 확률은 달라질 수 있다.
따라서 임계값 유지가 보안 수준 유지의 증명은 아니다. 다른 손가락/FAR 검증은
여전히 필요하다.

helper는 v6 응답 형식을 확인하고, 거절 원인을 추적할 수 있도록 상관/겹침/
타일 수/모호성/경계/재탐색 여부/소요 시간만 stderr에 남긴다. 영상, 템플릿,
사용자 이름, 경로는 로그에 남기지 않는다. 기존 4초 GPU worker와 6초 bridge
제한, 고정 프로토콜, root 갤러리 무결성 검사, 실패 시 거부는 유지한다.

## 2026-09-07 동일 자료 재시험

원본 기준 세션 `live-20260907-011121-680`의 25장을 고정하고, 이후 6개 세션
185개 저장 영상을 기존 설치 바이너리와 새 바이너리에 각각 전달했다.
테스트 영상을 기준 갤러리에 넣지 않았으며 파일 내용이 동일한 기준/검사
영상은 제외하도록 했다(이번 실행 제외 0개).

| 기존 인증 정책 통과 영상 | 158/185 (85.4%) | 166/185 (89.7%) |
| 비교된 접촉 중 한 번 이상 통과 | 139/159 | 143/159 |
| 기존 성공이 실패로 바뀐 영상 | — | 0 |

8개 영상이 추가 통과했고 그중 2개는 마지막 정밀 탐색으로 복구됐다.
최종 빌드 재시험에서도 같은 통과 결과가 재현됐다. 새 버전 비교 시간은 평균
약 316ms, 최대 약 759ms였다. 프로세스 시작·센서
캡처·44장 실제 설치 갤러리의 지연을 포함한 수치는 아니다.
최근 `063446` 세션은 11/14→12/14지만 접촉 단위는 9/10으로 동일하다.
해당 세션의 어려운 6번 접촉은 여전히 두 영상 모두 실패한다.

이 자료는 반복 사용한 **동일 손가락 개발 자료**이지 독립 실사용 FRR 측정이나
타인 지문 FAR 측정이 아니다. 실제 인증에서 방금 실패한 영상은 보관되지
않았으므로 이 재시험이 그 실패의 영상 원인까지 규명하지는 않는다.
실제 설치 갤러리는 44장이지만 이 시험은 오염을 줄이기 위해 원본 25장으로
고정했다. 실사용률로 읽으면 안 된다.

최종 빌드의 로컬 상세 결과는 `local-private/recognition/auth-v6-replay-g4y2isrd/summary.json`
(디렉터리 0700, 결과 0600)에 있다. 기준/바이너리 SHA-256 및 각 비교 결과를
남겼다. Python 집계와 C++ 실제 인증 정책의 185개 결과도 일치했다.
초기 빌드 재시험은 별도 `auth-v6-replay-ewrpb7k5` 디렉터리에 보존했다.

## 재현과 회귀 검사

`tools/vkmatch/evaluate_auth.py`는 읽기 전용 저장 자료 재생 도구다.
`--baseline`, `--candidate`, `--reference-dir`, 반복 `--session`, `--output-parent`
인자를 받는다. 새 비공개 결과 디렉터리를 만들며 기존 결과를 덮어쓰지 않는다.

`auth-policy-fail-closed`는 높은 종합 점수지만 모호한 후보/부족한 타일,
필수 필드 누락, 범위 밖 타일 수, 유효 후보 우선 선택을 확인한다.
`auth-search-geometric-controls`는 비생체 합성 영상의 소수 픽셀 이동·회전·크기
변환 복구와 평탄/독립 잡음 거부를 실제 GPU CLI로 검사한다. 이것 역시 다른
손가락에 대한 보안 검증을 대체하지 않는다.

최종 확인: CTest 5/5, Python 인증 설치 4/4, 관리자 안내 6/6,
갤러리/재생 정책 6/6 통과. 시스템 인증 파일·PAM·등록 자료는 이 변경에서
수정하지 않았다. 시스템 엔진 교체와 실제 실패 영상의 새 진단은 후속 단계다.
