# 지문 접촉영역 0/1 분할과 v7

## 왜 필요한가

108×88 센서 영상에는 지문이 닿지 않은 검은 보정 배경과, 지문 골 때문에 어두운
픽셀이 함께 있다. 단순히 `밝음=1, 어두움=0`으로 이진화하면 지문 골까지 배경으로
사라진다. 반대로 배경까지 매칭하면 두 영상의 공통 검은 영역이 점수와 정렬에
불필요하게 섞인다.

v7은 두 문제를 분리한다.

1. 드라이버의 접촉 기준과 같은 `24/255` 이상 픽셀을 시작점으로 한다.
2. 5×5 주변 지지가 7개 이상인 픽셀을 접촉 후보로 확장한다. 따라서 어두운 골은
   이웃한 밝은 능선/계곡 성분에 연결되어 지문 영역(1)으로 남는다.
3. 8방향 연결 성분 중 가장 큰 하나만 지문 접촉영역으로 남기고, 흩어진 센서
   잡음과 배경은 0으로 둔다.
4. GPU가 찾은 회전·이동·균일 크기 정렬 뒤, **양쪽이 모두 1인 교집합**에서만
   내부 명암 NCC와 융선 방향 상관을 계산한다. 보간 위치도 4개 마스크 중 60%
   이상이 1일 때만 사용한다.

이것은 지문을 템플릿으로 이진화하는 단계가 아니다. 0/1은 `접촉영역/배경`이고,
신원 증거는 그 안의 연속 명암과 융선 방향이다. 결과에는 원본 마스크나 좌표를
저장하지 않고 4×4 요약 비트와 면적 비율만 기록한다.

## 화면 표시

연구 화면의 비교 정지 영상은 변환된 기준 타일을 다음과 같이 표시한다.

- 회색: 배경(0)으로 분할되어 비교에서 제외
- 노랑: 접촉영역(1)이지만 국소 대비·방향 특징이 부족
- 초록: 접촉영역 내부에서 지지된 비교 근거
- 빨강: 접촉영역 내부지만 비교 근거가 부족
- 파랑 테두리: 물리적 센서 가장자리를 뺀 비교 범위

`ridge_roi` JSON에는 `binary: true`, 각 접촉 면적, 정렬 후 교집합, 4×4 요약
마스크를 낸다. v7 인증 helper는 이 필드가 없거나 교집합이 50% 미만이면
실패-닫힘으로 거부한다.

## 고정 자료 재생

기준 세션 25장과 독립 저장 검사 185장을 대상으로, 기존 v6 결과와 v7의
마스크 연산 결과를 파일별로 비교했다. 둘 다 같은 v6 후보 탐색(균일 크기
0.95~1.05)과 동일한 인증 임계값을 사용했고, 차이는 접촉영역 교집합뿐이다.

| 측정 | v6 | v7 ROI |
| --- | ---: | ---: |
| 인증 조건 통과 | 166/185 | 166/185 |
| 기존 통과가 실패로 변경 | — | 0 |
| 새로 통과 | — | 0 |

실제 저장 프레임 하나의 진단값은 기준 접촉영역 90.5%, 검사 접촉영역 91.4%,
정렬 후 유효 교집합 74.7%였다. 마스크가 배경을 빼면서도 유효 능선 영역을
제거하지 않았음을 보여주는 사례다.

이 결과는 반복한 동일 손가락 개발 자료이고 타인 지문 FAR 또는 독립 FRR
검증이 아니다. 따라서 v7 소스는 빌드·테스트됐지만, 새 시스템 PAM 엔진으로
설치하지 않았다. 새 라이브 샘플과 다른 손가락 음성 대조가 확인된 뒤에만
배포 후보가 된다.
